OpenCode UX+ (fengwuxin) JetBrains Plugin Changelog

26.9.2508

  • Removed the Share Session button (opencode v2 has no sharing API, so it did nothing)
  • Markdown rendering now uses the official opencode theme colors: lavender headings, orange bold text, green inline code, peach links and colored list markers
  • Per-message costs below $0.01 show more decimals instead of rounding to $0.00

26.9.2507

  • Model picker no longer syncs with the opencode desktop app; the plugin owns its model list
  • All models of enabled providers are listed by default; "Manage models…" hides individual models
  • Removed the SQLite dependency and the desktop-client state reader from the plugin
  • Message input placeholder falls back to "Hello owner" when no username is configured

26.9.2506

  • Message input placeholder now greets the configured user ("Hello <username>")

26.9.2505

  • Settings → Models: the enabled-provider checkboxes now keep the saved state (the server exposes disabled providers as experimental.policies, both config shapes are read)
  • Model picker: favorites/recent entries from disabled or unavailable providers are no longer listed
  • Reasoning effort (thinking depth) keeps working after saving settings: the provider list is no longer overwritten by the empty response the backend returns while reloading, and it retries until ready

26.9.2504

  • Settings → Models: the list now contains every available/connected provider (plus currently disabled ones), so a disabled provider can be enabled again
  • Models of disabled providers no longer appear in the model picker; the picker also filters by the effective config so changes apply without restarting the server
  • Removed the "(Enter to send)" hint from the message input placeholder

26.9.2503

  • Settings → Models: providers are now enabled by default ("Enabled Providers"); uncheck one to disable it
  • Message input: Enter sends the message, Cmd/Ctrl+Enter (or Shift+Enter) inserts a new line
  • Message input starts two lines high
  • Enter still lets the @ mention / command popovers handle the key while they are open

26.9.2502

  • Fix reading the desktop client's model visibility inside the IDE (SQLite driver is now loaded through its DataSource, which works in the plugin classloader)
  • Model picker retries while the opencode backend is still warming up instead of staying empty

26.9.2501

  • Model picker now mirrors the opencode desktop client: only the models enabled in its Manage models settings are shown
  • Model visibility is read from the desktop client's local state (SQLite, read-only); changes appear the next time the picker opens
  • Without a desktop client, the picker falls back to "newest model per family from the last six months" with a local Manage models dialog
  • Models disabled in the opencode configuration are skipped, and release dates are read from the v2 model catalog

26.9.2404

  • Plugin icon: the opencode logo (opencode.png at the repository root, shipped as a vector pluginIcon.svg)

26.9.2403

  • Pasting images works again: inside the IDE the clipboard is read by the plugin, because JetBrains' embedded browser does not always expose clipboard images to the page

26.9.2402

  • Settings: saving works again — changes are written to the global opencode.json(c), since the opencode v2 server has no config write API
  • Settings: failed saves show the reason in the panel instead of silently doing nothing
  • Settings: config fields now use the opencode v2 names (update, snapshots, plugins) so the current values are displayed correctly

26.9.2401

  • Fix the reasoning effort selector offering "0 / 1 / 2" instead of the model variants (opencode v2 returns variants as an array)
  • Reset a stored reasoning variant when the selected model does not offer it

26.9.24

  • Show sent user messages again (opencode v2 delivers them through the inbox event)
  • Scope the session list to the current project
  • Plugin id, name and vendor are now fengwuxin

26.9.23

  • opencode v2 support (v2 only, v1 is no longer supported)
  • Runs the locally installed opencode serve and connects the IDE tool window to its web UI
  • Handles the opencode v2 HTTP basic auth automatically (password is injected on launch)
  • New setting: path to the opencode executable (auto detected when empty)
  • Removed bundled v1 backend binaries and the v1 REST/ideBridge coupling
  • "Add to context" / drag and drop fall back to copying the path to the clipboard
